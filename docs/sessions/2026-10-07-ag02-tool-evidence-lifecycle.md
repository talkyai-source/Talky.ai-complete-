# AG02: current-turn tool evidence and speech boundary

Status: bounded local correctness repair; AG02 and paid-use acceptance remain open.

The existing opt-in knowledge-tool path had three related defects. A direct answer on a new turn retained prior knowledge evidence and could repeat its price without a current lookup. Weak or unavailable results were marked as successful because the streamer compared result prose with one no-match string. A knowledge-only decision round could also reach speech before its lookup completed, producing premature speech followed by the actual answer.

`TurnStreamer` now clears evidence and grounding at turn entry, before selecting tool, injection or inline behavior. Current injection and inline sources rebuild grounding normally. A completed knowledge lookup records its canonical evidence status, with `matched` the sole successful result; malformed or absent status is unavailable. Each lookup replaces local speech grounding too, so another distinct lookup in the same decision round supersedes earlier facts. The existing provider buffering option now also covers knowledge-only tool turns. Action execution behavior is unchanged.

The exact source commit and normalized input hashes are recorded in `artifacts/ag02-tool-evidence-lifecycle/commands.json` and `source-hashes.json`. Checks used base `76ba91eabfea5cbf1f6b106202e16a5dbf858b1b` plus the reviewed two-file change. Commit binding is source parity, not a rerun. Root separately owns the current-turn prompt alignment in `ca5d6f0d`; this owner run does not claim to test that later composition.

## Qualification limits

The existing `VOICE_KB_MODE=tool` opt-in and default injection selection are unchanged. This does not introduce automatic recovery, a new retriever, provider, model, threshold, synonym or gold-fixture change. A model-authored query may still drift from the caller's original question: authored lexical coverage of that rewritten query does not prove semantic equivalence or correct answer generation. These controls do not qualify live model decisions, speech/audio quality, provider timing or customer acceptance.

The fix addresses prior-turn retained evidence and ordered lookup supersession on the ordinary sequential turn path. It does not claim to resolve every possible overlapping/cancelled lookup or multiple-source semantic issue. In particular, shared query terms can leave multiple products in the current retrieved passages; clearing stale buffers does not establish which product the caller meant. The last structured tool result remains historical until another tool completes; current-turn grounding and evidence are cleared independently. Strict buffering uses existing provider behavior, including its answer-round buffering, and is not evidence of improved latency.

Tests use the explicitly selected existing local Python 3.12.12 virtual environment and recorded installed package versions/paths. This is not an exact requirements installation or a production-runtime qualification. No feature-freeze, gate, deferred-package or release status changes are made here.
