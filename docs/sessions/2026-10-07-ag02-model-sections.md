# AG02 model-selected source catalog and reader — 2026-10-07

Source commit: `3d94726e3086c68700a7a55b9140b8c206311184`, based on `0270d44981a4218e16619d7a65b4ffb7dc79a8ef`.

This owner slice replaces query search inside the live knowledge tool with exact, call-scoped source-section reads. It is intended to integrate with the separately owned traditional streamer, bounded tool continuation, native bridge and prompt simplification changes. This source commit alone is not a complete deployable migration of those adapters. The historical lexical qualification profile does not qualify this new flow.

The conversational model receives a compact catalog and chooses server-owned section references. The same tool accepts exactly one of `section_ids` (one to three distinct references) or `catalog_offset` (a nonnegative integer, not a boolean). Unknown arguments, caller-supplied scope, unknown references, and query strings are refused. A catalog page is navigation only. A read returns authored bodies with actual same-source ancestors and provenance; generated summaries, answers, aliases and lexical coverage never authorize facts. Available means the section was read, not that it answers the caller's question.

The catalog uses numeric tree order and complete bounded pages with explicit next offsets. Each page is bounded to 8,000 entry characters; reads are bounded to 12,000 authored context characters. Oversized entries or whole section/ancestor context return `too_large`, without silently cutting conditions. Missing, disabled, cyclic, cross-source, revision-inconsistent or ambiguous parents do not leave an orphan price readable. Skipped Markdown heading levels and genuinely flat legacy nodes remain supported. A heading-only selection supplies no factual success. Preambles remain sibling sections, never invented ancestors. Descendant sections, relevance to the question, and selection of all applicable topics remain the model's responsibility.

Every saved non-none campaign mode now prepares the same model-selected catalog; the storage mode strings are retained for compatibility. Outbound and browser-test calls explicitly pin published enabled rows at setup (`call_snapshot`); edits apply to a later call. Inbound calls continue using the immutable admission snapshot (`admission_snapshot`). No per-turn refresh, reindex, migration, provider, vector database or public endpoint was added. The existing diagnostic search API and lexical ranking were not changed; the existing loader only additionally projects `parent_id`.

Preparation occurs before session creation in outbound prewarm, inbound config and browser campaign-test paths. Native instructions and knowledge capability therefore exist before provider connection. Traditional sessions inherit the same context. Native initial profile evidence includes the catalog checksum; the existing bridge database pool is retained separately for contact revision persistence and final flush. Static no-catalog campaign preview stays unchanged; actual runtime supplies the unavailable-source capability note. Tool wire results include each authored passage once, with provenance; aggregate diagnostic text is not duplicated on the wire.
