## Covered boundaries

- Explicit denial survives 30 ordinary caller turns; a genuine later caller affirmation can supersede it.
- Script quotations, another person's statement, conditional or negated reporting, another supplier's customer relationship, and an assistant/campaign assertion cannot manufacture the caller's relationship.
- Being a merchant, not having a card terminal, or not having used card payments does not by itself identify an existing customer or deny a relationship.
- Late older affirmation cannot reverse newer denial. Delayed older denial remains relevant before or after a newer ordinary final when no later relationship assertion supersedes it.
- Duplicate finals do not repeat state or action admission. Current correction/retraction restores the prior relationship without erasing separately established identity, confirmed contact, or successful tool evidence.
- One hundred synthetic turns keep the item map within 64 entries, contact history within 12 entries, and the state prompt within its declared bound. Evicted unowned finals and assistant statements do not restore customer status in the tested path.
- Revision metadata requires an exact owned user row, nonempty bounded provider item ID, and valid index/order. Original content, timestamp, other metadata, and row count are preserved. Only the latest revision text is retained, capped at 4096 characters with full-content digest and explicit truncation/retraction facts. Sealing rejects a late annotation and does not recreate a buffer.
- Read review of the action executor confirms it captures the admission token before its first asynchronous context read and checks the confirmation token again before the external-effect boundary. The native owner separately tests suspended executor windows; this independent module asserts the bridge's invalidation signal without performing an external action.
- Late denial prevents an already admitted utterance from beginning and stops remaining chunks when one submission has already occurred. These cases require exactly one normal provider continuation and no repair call claiming the response was wholly unheard. Harmless late finals before/during playback do not cancel a valid response. A completed, synthetically acknowledged historical utterance retains its history and is not retroactively cleared. Already submitted audio is not treated as undone or necessarily heard.
- Final read review of native playout confirms relationship revalidation before transport submission, owned-utterance/status checks after gateway awaits, and preservation of uncertain partial-delivery evidence even when a gateway returns after cancellation. Recovery uses the existing single-repair budget and normal continuation wrapper shared by OpenAI and xAI; it does not add a recovery framework.
- Final read review of traditional scheduling confirms a stamp allocated synchronously at accepted final/queue insertion, exact duplicate reuse, queue-drain copying, and false-barge replay only while that accepted turn remains current. Coalescing retains a typed predecessor containing only the latest explicit relationship and provenance. It cannot replay dropped contact/action/refusal fields. The owner's actual handler/TurnEnder/barge lifecycle regressions cover this scheduling contract; they are separate from the 34-case independent count.
- The parent's traditional guard regression runs the actual streamer and observes submitted speech/history with fake generated text. It verifies guard admission after history pruning, not real-model semantic accuracy.

## Remaining scope limits and handoff

The revision metadata is evidence preservation, **not a canonical transcript rewrite**. The independent test deliberately confirms that plaintext still contains the original statement. Canonical JSON/plaintext interpretation and Leads/Sales Hub extraction must become revision-aware under AG05; this package does not claim that correction reaches those consumers. AG03 intentionally preserves confirmed contacts through replacement; AG05 must examine whether original confirmation plus revised speech instead requires safe contact invalidation or reprocessing. The NULL-value label in `Talk-Leee/src/components/calls/lead-details-panel.tsx` likewise needs an actual durable status-to-API-to-UI trace before a NULL tombstone can be called a caller refusal.

The tests establish the supported final/duplicate/current-replacement and retained identity paths. They do not certify arbitrary provider protocol violations, unlimited replay recognition after identity eviction, process restart recovery, or automatic call resumption. Legacy no-ID events and unstamped traditional compatibility callers have the documented fallback identity behavior, not a temporal-order guarantee. Final review found no further material regression in the bounded implementation paths described above; that is not a claim that the entire voice system has no defects.

The relationship parser remains deliberately conservative and is not a language-understanding guarantee. Customer status stays unknown without supported caller evidence. Production answer quality, provider behavior, interrupted audio, hearing, latency, and the existing AG02 retrieval target gaps remain separate qualification work. Read-only AG04/AG05 inputs are recorded in `next-package-inputs.md`.

Independent ownership is limited to `backend/tests/unit/test_ag03_relationship_acceptance.py` and the independent evidence files in this directory. Runtime changes belong to the shared-state, native, and parent owners. No commits or deployments were made by this review.
