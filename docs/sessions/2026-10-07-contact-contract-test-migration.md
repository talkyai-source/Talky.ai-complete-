# Contact contract test migration and foreign-field preservation

Source/test commit `caabe89c`, based on integrated `2d17c523`, updates the four assigned modules: contact capture state machine, contact pause/punctuation, native relationship ownership, and AG05 native contact revision. Root reviewed the small application correction and the revised native tool/revision and transport controls before commit.

The tests now distinguish retained pure legacy parser diagnostics from active model-driven contact orchestration. Native runtime scenarios issue `record_contact` through actual provider event parsers and the bridge; they no longer expect caller words or played prose alone to save/confirm contacts, force a scripted readback, or interrupt the model with a contact directive. Model decisions are synthetic, so these tests do not measure the model's understanding or third-party contact ownership accuracy. Neutral prompt assertions retain candidate/status visibility without prescribing speech. One obsolete source-string assertion about the removed runner classifier was retired because actual source-binding scenarios now cover that boundary.

Source ownership, duplicate/late caller handling, current ASR revisions, independent contact evidence, transcript audit preservation, contact persistence/revocation, caller opt-out and pending-action invalidation remain tested. The suppressed-cancellation cases now use an actual speech interruption instead of a relationship regex: a gateway that swallows cancellation cannot resume the old utterance or manufacture completed playback. Ordinary model prose no longer triggers an extra semantic repair or shutdown. The old standalone provider interrupt API diagnostic remains a legacy transport check; active contact capture does not call it.

The migration exposed one compatibility regression. Given an emulated legacy state with a phone scalar but no structured phone capture, changing the email via either a native source revision or the real model tool called `dataclasses.replace`; `CallState.__post_init__` then silently lifted the untouched phone into a new capture. No current application producer of this deliberately emulated old shape was found, and no observed live incident is claimed. The narrow `_with_contact_changes` helper restores untouched capture objects after replacement. It is used only in the contact mutation/revision paths and leaves global CallState behavior unchanged. The retained assertion fails through both paths before this correction and passes after it.
