# CP07 external notification delivery contract review

Date: 4 October 2026. Source audit baseline: `8f11f335e21bd29731e880ef0116472acc41f59d`, followed by the narrow test-endpoint repair described below. This is a local source/test review, not a production check or receiver acceptance test. No provider request, email, webhook delivery, customer call, deployment, or production mutation was performed.

**External customer alert automation remains blocked / not done.** Identity isolation and disabling unsupported browser routing are containment; they do not establish reliable background delivery or complete CP07. CP06 billing recipient policy remains deferred and is not redefined here.

## Missing contract and egress boundary

No reusable arbitrary-HTTP webhook egress contract was found in the current backend. The SIP-specific resolver at `backend/app/api/v1/endpoints/telephony_sip/trunk_probe.py:41–74` rejects nonpublic DNS answers and connects to a pinned address, but it has a SIP/PBX-specific private-target override. It is not an HTTP redirect/TLS/receiver policy. The document-host allowlist at `backend/app/domain/services/billing_invoice_projection.py:54` validates displayed Stripe links, not outbound customer requests. The outbound signing helper at `backend/app/core/security/webhook_verification.py:184` can construct HMAC headers but is not a dispatcher or receipt mechanism.

Therefore copying a browser URL into a server request would create a new network trust boundary without a verified HTTP SSRF control. No such copy or server send was added.

The precise completion gap is an approved, bounded contract for the **existing alert behavior**: authorized tenant/user and event selection; supported destination identity and revocation semantics; frozen event-specific payload/destination; stable event/destination deduplication; permitted HTTP egress including DNS/redirect handling; truthful accepted/failed/unknown receipts; and a retry/reconciliation policy matching that receiver's proven idempotency support. Existing generic HTTP endpoints cannot be assumed to honor an idempotency header. A timeout after possible acceptance must remain unknown unless independent receiver evidence resolves it. This is a scope decision and acceptance prerequisite, not an instruction to build a new automation platform.

Until that decision and evidence exist, external routing is unavailable, local notifications require the dashboard session, and authoritative lead capture/payment state remains separate from notification delivery.

## Narrow latent test-endpoint truth repair

The baseline owned endpoint lookup in `webhooks_admin.test_webhook` returned `{success: true, delivery_id: webhook_id}` without sending or recording anything. This was a latent code defect in an unmounted router, not evidence that a live user had received a false successful test.

The repaired function preserves `require_admin_tenant` and both endpoint/tenant filters. An owned saved endpoint now returns HTTP 501 with `outbound_webhook_delivery_unavailable` and an explicit statement that no test notification was sent. Foreign or absent configuration stays HTTP 404. Adapter storage errors and raised storage exceptions return sanitized HTTP 503 `webhook_configuration_unavailable`, not false absence or success. It performs no write or outbound request. No route mounting, permission, credential or provider behavior changed.

The existing `billingFetch` helper delegates to the shared API client and propagates non-2xx errors (`Talk-Leee/src/lib/billing-api.ts:28–42`); `useTestWebhook` preserves that rejection. There is no mounted test button requiring a new success/error mapper.

This proves the local handler/error contract under synthetic storage fixtures. It does not prove deployed route availability, browser identity isolation, closed-browser delivery, external receiver idempotency, SSRF resistance of a future sender, inbox receipt, or production operations. Those limits remain explicit; the external automation feature is **blocked / not done**.

The harness uses actual notification modules with synthetic identity and event adapters; it deliberately excludes real AuthProvider/cookie login and external delivery. Reproduction source, exact source/bundle hashes, final screenshots, a preserved before-fix clear-race capture, and cleanup evidence are saved in the same artifact directory. This does not change the blocked external-delivery conclusion.
