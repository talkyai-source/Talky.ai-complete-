## Confirmed source gaps and existing protections

1. [Installer](../../backend/systemd/install-services.sh#L21) symlinks and enables units. It does not provision service identities, group memberships, secret permissions or runtime directories. None of the canonical service units declares `UMask`, `NoNewPrivileges`, `ProtectSystem`, `ProtectHome`, `ReadWritePaths` or a capability bound. This is a source configuration gap, not proof that the deployed host lacks separate drop-ins.
2. API, three workers, cleanup, migration, trunk status and gateway reference the same backend EnvironmentFile. Every configured variable is supplied to each corresponding process. Exact contents/ownership were not read, so minimal per-service credential exposure is unverified. [Core config](../../backend/app/core/config.py#L15) also identifies the backend `.env` file; [settings](../../backend/app/core/config.py#L62) enables dotenv loading. File-read behavior must be considered when changing process identity, not only systemd's ability to read EnvironmentFile.
3. The PJSIP module formerly assumed the backend was `admins` and said sudoers authorized reload. Its documentation now describes the configured runtime identity, explicit operator provisioning, the restrictive `asterisk:asterisk` setgid 2770 directory/0640 file requirement, and the actual direct CLI invocation. No runtime command, mode, group, user or reload behavior changed. CLI acknowledgement alone does not prove that Asterisk can read and load the generated file.
4. [Dockerfile](../../backend/Dockerfile#L38) creates a UID 1000 `talky` user, owns `/app` accordingly and selects `USER talky`. The [Compose backend](../../docker-compose.yml#L86) uses this image and full backend `.env`; default local recordings have no declared durable backend volume. This is not evidence of durable storage or installed permissions.
5. [Helm values](../../infra/helm/talky/values.yaml#L147) enforce nonroot UID/GID 1000, no privilege escalation, read-only root filesystem and dropped capabilities. [Deployment mounts](../../infra/helm/talky/templates/deployment.yaml#L124) provide only `/tmp` emptyDir. The relative `/app/recordings` default therefore needs an explicitly configured writable persistent volume for local retention; `/tmp` is ephemeral. The separate [raw Kubernetes reference](../../infra/k8s/backend-deployment.yaml) does not declare the same security context or writable volume. Do not describe all deployment variants as equivalent.
6. [Application logging](../../backend/app/core/app_bootstrap.py#L43) uses stream logging rather than a configured application log file in the scoped path. Journald/container logging and [NGINX log files](../../infra/nginx/talky.conf#L122) are separate operator-owned sinks. No writable application log directory was established as a prerequisite by this review.
