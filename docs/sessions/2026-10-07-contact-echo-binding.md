# Canonical contact evidence after echo cleanup

This is a bounded follow-up to the model contact refactor, reproduced on owner source `d624f622`, repaired in source commit `71165202` after root review. `TranscriptHandler` sanitized and saved the caller's final words, then bound the accepted caller order to that row. Later `TurnEnder` removed echoed assistant words from the conversation message. `TurnRunner` attempted to bind that cleaned text against the saved row's original hash, so the exact source check correctly failed and `record_contact` returned unavailable even for the remaining legitimate email.

The fix resolves canonical effective caller text and its source tuple together through `TranscriptService.caller_evidence`. Existing `caller_source` remains a source-only compatibility wrapper over the same unique-row/revision checks. `TurnRunner` binds the canonical bundle while preserving its cleaned message in model history. `bind_contact_turn` still verifies the exact hash; no contact parser, classifier, inferred source, or relaxed revision validation was added. The transcript is not rewritten to pretend echo cleanup was an ASR revision.

Six added controls cover the actual `TranscriptHandler` → `TurnEnder` → `TurnRunner` → `record_contact` path with echo+email, the same input with privacy sanitization, canonical revised text, duplicate ownership, retraction, and malformed revision metadata. The actual pipeline controls assert that model input is cleaned, contact saving is acknowledged by the existing synthetic SQL port, and persisted contact evidence hashes the unchanged sanitized canonical row. Unrevised rows remain unrevised; actual ASR revisions retain their original text. One existing AG05 ownership test now issues real model contact-tool calls instead of expecting the removed regex parser, while retaining source row/hash, confirmation order, and no-invented-readback assertions.
