# Model-driven name and company capture

Source: `1b6f4a8ab0090298b18234e2cb85dd1126f66b73`, based on `6c9eed991a7c69afd70536379427933f099052d9`. Exactly 11 application paths and 6 test paths; [final source manifest](artifacts/model-identity-capture/final-source.json) lists every file. No schema migration or new service/provider.

The live recording tool previously accepted only email and phone. Post-call business-detail extraction also excluded names and companies. Existing `call_lead_details` text/audit columns and the Captured Details panel already supported displaying them, so the missing boundary was recording and evidence-aware persistence.

`record_contact` now accepts `full_name` and `company_name`. Set stores an unconfirmed candidate; a later model-interpreted caller agreement can confirm that same value. Correction removes old confirmation; withdrawal preserves a null cancelled row. Names and companies each have one current entry, with no add operation or name splitting. Spelling, case and Unicode are retained; only bounded text syntax is checked. Selected-value compare-and-set, current canonical caller quotes/revisions, source ownership and exact per-field save acknowledgements remain shared with email/phone.

Persistence and projection understand these two versioned text identities. A revised/missing source cannot remain an active confirmed fact, even when revocation cannot commit. Manual edits/removal keep precedence over later model writes, while existing unversioned/imported generic text keeps its prior behavior. The existing expanded Captured Details UI displays name/company, confirmation and withdrawal statuses with source references. Imported/generated lead display names remain independent; this repair never splits a caller name into `leads.first_name`/`last_name` or overwrites campaign/imported identity.

The traditional/native guides now mention name and company in the existing contact paragraph and refer to the selected candidate. Governed versions advance to `lead_gen@15`, `customer_support@13`, `receptionist@13`, and `realtime@10`; prior hash entries remain unchanged. No persona or provider settings changed.
